# Security and performance remediation plan

Status: local implementation delivered; extended acceptance and release/deployment gates remain open. Based on the 5 September 2026 review of commit `7a616cd`. See [implementation results, measurements, and remaining gates](security-performance-implementation.md).

Scope: address all 18 numbered findings (F01–F18) and all ten additional observations (O01–O10). Deliver this in reviewable changes, with an early containment release rather than waiting for every optimization. The original planning turn made no code changes and ran no tests. The subsequent implementation turn changed local code/docs and ran the verification recorded in the implementation report. No release or deployment was performed.

## Design commitments

- Preserve directional keys, transcript binding, per-stream key separation, authenticated sequence numbers, replay protection, and the nonce ceiling. Do not introduce unsynchronized encrypted writes or restart a nonce sequence under an existing key.
- Account for resources before accepting sockets, allocating decoded output, enqueueing frames, or expanding archives. Budgets include queued and in-flight work, not just completed payloads.
- Distinguish transport connection, authenticated peer, verified content, published output, and acknowledged completion. Success must not precede the operation it promises.
- Preserve the existing frame format where possible. New peer-visible behavior must be negotiated and authenticated, or require a protocol-version change; never silently reinterpret an old payload.
- Prefer bounded per-session state and one-time markers. No persistent inbox, outbox, or event-history subsystem is needed.
- Implement straightforward correctness fixes directly. For suspected throughput bottlenecks, measure first and retain only optimizations that improve the target workload without breaking bounds.

## Recommended behavior decisions

These decisions were adopted in the implementation. The finite disk defaults are 1 TiB per decoded transfer and 1 TiB per expanded archive; zero selects that default, and positive byte limits provide the trusted-use override.

| Decision | Recommendation | Consequence |
| --- | --- | --- |
| Meaning of Complete | Verified content successfully finalized by the destination sink | Not a universal power-loss durability guarantee; stdout and browser Blob downloads have narrower guarantees, documented separately |
| Archive destination | Publish every extraction through one new destination directory using atomic no-replace semantics | A single logical folder keeps its expected root; flat multi-root archives receive a named wrapper instead of merging into an existing directory |
| Unsupported atomic publication | Fail explicitly and retain recoverable staging when appropriate | Never silently fall back to a potentially overwriting rename |
| Proxy forwarding | Honor forwarded addresses only from explicitly trusted proxy addresses/CIDRs | Existing proxy deployments receive a migration example; direct connections remain untrusted |
| Unknown-size and expanded output | Require a finite receiver policy; expose limits through CLI/config and document an explicit trusted-use override | Select numeric disk quotas against documented supported workloads before release; peer metadata cannot raise a user limit |
| Browser memory fallback | Explicitly choose a bounded fallback when streaming is unavailable | Picker cancellation cancels; permission/activation failures do not silently switch to RAM |
| TURN | One credential issuance per paired session, shared consistently with both participants; bounded lifetime and public relay quotas | Static shared credentials remain an explicitly unsafe public-service option or are disallowed in public mode |

Initial engineering targets: keep the browser's existing 8 MiB queue budget but enforce it, add a frame-count bound, and start parallel reassembly with a 32 MiB payload budget plus separately bounded decoder/per-stream overhead. These are implemented application-buffer budgets, not promises about total process RSS. Tune with the validation matrix; never return to an unbounded fallback.

## Phase 1 — Contain the immediate exposures

Goal: a small compatible patch release that reduces the highest risks while the lifecycle work proceeds. A mitigation does not close a finding whose full fix appears in a later phase.

- [x] **F01 — Patch every build path.** Select a currently supported Go toolchain with fixes for the review's applicable advisories. Align local guidance, `go.mod`/toolchain policy, CI, release builds, and Docker's Go builder. Check the actual compiler recorded in every built binary. Re-scan dependencies; evaluate symbol matches individually. Rebuild static executables and containers rather than only replacing runtime images.
- [x] **F02 — Bound decompression before allocation.** Configure Go decoded-output and window limits, and use bounded output storage. Audit the browser decoder's preallocation behavior and use a genuinely bounded implementation; do not assume a post-decode check or supplied buffer alone bounds decoder internals. Reject oversized uncompressed chunks too. Cover declared-size, unknown-size, concatenated, malformed, and excessive-window zstd inputs. If browser decoding cannot be made bounded promptly, reject compressed browser receives with a clear error until the replacement is ready.
- [x] **F03 — Bound pre-registration sockets.** Reserve global/per-IP active-socket capacity before upgrade and release it exactly once on every exit. Budget paired sockets separately from session counts so legitimate two-peer sessions still fit. Add a short first-message deadline, bounded signaling traffic, and explicit close/cancel on ping failure. Bound limiter bookkeeping and use one consistent client-IP resolver.
- [x] **F03/F11 — Stop holding browser signaling sockets during user decisions.** Fetch preview information first; show a confirmation button even without a preview. Acquire the save handle directly inside its click handler, before asynchronous connection work, and connect/join afterward. A cancelled picker must not register a receiver. Delay opening the writable replacement until authenticated metadata is accepted.
- [x] **F04, containment — Bound confirmation and accepted handshakes.** Add a candidate confirmation timeout and an inbound-handshake concurrency cap. Cancellation must close or deadline the underlying I/O. This removes indefinite hanging; keeping good candidates alive is Phase 2 and remains required.
- [x] **F05, containment — Make browser limits real.** Validate frame lengths and phase-appropriate control sizes; check byte and frame-count limits before enqueueing. Bound partial-frame storage and in-flight decryption as well. On a hard-cap violation, close once, release queued buffers, and reject every pending reader/writer. Phase 4 adds cooperative flow control for legitimate slow receivers.
- [x] **F06 — Enforce metadata-first delivery.** Add explicit MultiStream receive phases so buffered data cannot outrun initial metadata. Preserve the Done data barrier and immediate terminal cancellation. Specify legal controls for both sending and receiving roles; do not impose a receiver-only metadata requirement on the reverse direction.
- [x] **F07 — Abort failed browser output.** Extend `ChunkWriter` with abort semantics and one cleanup owner. Abort on checksum/count mismatch, malformed input, decryption failure, remote error, cancellation, and write failure; close only on verified success. Phase 3 fixes the ordering relative to Complete.
- [x] **F08 — Fix boolean parsing.** Parse `SP2P_TRUST_PROXY` using the existing boolean helper, with explicit coverage for absent, true, false, 1, 0, and invalid values. Complete trusted-proxy source restrictions in Phase 5.
- [x] **F16 — Centralize HTML security headers.** Apply headers to canonical and direct HTML routes, redirects/errors where applicable, and add CSP frame protection. Verify `/`, `/r`, and `/receive.html`; preserve script/bootstrap content negotiation.
- [x] **F17 — Sanitize remote terminal text.** Use one display-boundary sanitizer for filenames, remote errors, versions, addresses/details, and saved-path messages. Escape terminal controls without damaging ordinary Unicode. Keep trusted UI escapes separate and preserve the JSON event contract.
- [x] **O06 — Release rejected receiver slots.** Validate peer compatibility before attachment, atomically with session admission where needed. Audit all post-attachment exits for cleanup and support a subsequent valid join.
- [x] **O07 — Bound UPnP cleanup.** Use context-aware deletion with an independent short cleanup deadline and bounded HTTP I/O. Cleanup must finish even if the transfer context is already cancelled or the router stops responding.

Exit gate: focused regression tests establish bounded failure behavior, correct cleanup, and preservation of the existing CLI/browser happy paths. Do not advertise F04/F05/F07 as fully resolved until their later phases pass.

## Phase 2 — Make connection selection and parallel ordering reliable

Depends on Phase 1 limits. Finish this before adding parallel writer throughput optimizations.

- [x] **Protocol design gate.** Specify the authentication, winner-selection, secondary negotiation, and credit contracts before implementing peer-visible changes. Phases 2–4 form one versioned transfer release while signaling stays compatible with 0.4.0. Transcript-bound capabilities select v3 between updated peers or v2 with an old peer, without manual controls or coordinated client/server upgrades. V2 omits v3-only frames and warns without prompting. Do not ship an intermediate client that advertises a version whose required behaviors it does not implement.
- [x] **F04 — Select an authenticated, agreed connection.** Keep TCP/WebRTC alternatives alive while candidates authenticate. Inject candidate validation from the flow layer so connection management need not own session secrets. A bad/slow candidate closes locally without terminating healthy candidates. Bound total establishment time and candidate count.
- [x] **F04 — Preserve convergence and key safety.** Design an authenticated winner-selection exchange so both peers select the same connection under asymmetric timing. If authentication is performed on multiple candidates, bind proofs to fresh candidate challenges and the existing session/role transcript; do not reuse a replayable proof as candidate identity. Send no encrypted file data until selection is agreed. A new attempt that would restart frame counters must derive fresh keys. Require the same candidate handshake for all v3 peers, including browsers; unauthenticated signaling client-type hints must not bypass it. Keep v2 interoperability through transcript-bound version negotiation and bound the browser's combined candidate/confirmation reader.
- [x] **F09 — Bound reassembly by bytes and entries.** Reject stale/duplicate global sequences and malformed sequence encodings; check arithmetic overflow. Cap pending controls and validate Done counts against transfer state. Account for active reads/decrypts as well as the map. Ensure capacity handling cannot block every stream while the missing next frame waits behind unrelated data: reserve bounded progress capacity or fail deterministically instead of deadlocking.
- [x] **O08 — Preserve secondary stream identity.** Choose the simplest safe initial policy: enable parallel transfer only when every requested secondary index succeeds and both peers confirm that result; otherwise close secondaries and mutually fall back to the primary. Preserve original indices for key derivation. Do not compact arbitrary survivors or compare counts alone. A future subset optimization must exchange the actual index set over the authenticated primary.
- [x] **F06/F09 — Exercise terminal ordering.** Verify metadata-first, ordered data, Done-after-data, immediate cancel/error, and shutdown with missing sequence gaps. Negotiation failures must not leave stale control frames for the file receiver or silently fall back after losing framing synchronization.

Exit gate: deterministic buffered-startup and asymmetric-handshake schedules pass; stalled or hostile candidates cannot steal the whole attempt; no duplicate nonce or mismatched secondary key assignment is possible in supported schedules.

## Phase 3 — Make receive output transactional

Depends on Phase 1 abort handling. Coordinate completion timeouts with Phase 4 liveness.

- [x] **F12 — Separate verification from acknowledgement.** Refactor the Go receiver into explicit receive/verify, sink-finalize, and completion stages, or provide a finalizer with equivalent ownership. The current flow uses `io.Pipe`: close the payload side after verification so copying/extraction reaches EOF, await the consumer's close/commit result, then send Complete. Do not install a callback that waits for pipe EOF while leaving the pipe open.
- [x] **F07/F12 — Unify sink outcomes.** Disk sinks expose write/finalize/abort; the browser closes its writable stream before Complete. Check Go temporary-file close errors. Aggregate metadata, byte counts, hash validation, and output finalization before reporting success. A memory fallback promises a verified Blob ready for download, not that the browser saved it to disk; a caller-owned stream promises accepted writes, not rollback or downstream durability.
- [x] **F18 — Publish atomically without replacement.** Stage on the destination filesystem and publish a single logical directory for archives. Implement and verify native no-replace operations for supported platforms; preserve the regular-file hard-link path where suitable. Remove check-then-rename fallbacks. Refuse unsupported unsafe publication and never merge into pre-existing directories implicitly.
- [x] **F18 — Define failure ownership.** Abort before publication removes only owned staging; after publication, loss of Complete/FinAck must not delete the published output. Report an unconfirmed sender outcome if confirmation is lost. If cleanup fails, return the exact recovery path and avoid deleting concurrent user changes. Document that atomic publication is not automatically crash durability.
- [x] **O05 — Enforce transfer and extraction quotas.** For known-size transfers, reject bytes beyond metadata before writing and require exact size at Done; distinguish an empty file from `StreamMode`. Verify archive size accounting against the actual emitted TAR, including PAX headers, long paths, large numeric fields, and input changes. Count expanded regular-file logical sizes, including sparse output, before extraction. Use overflow-safe arithmetic and independently enforce receiver-configured unknown-stream and expanded-output limits.
- [x] **F15 — Preserve browser archive paths.** Use USTAR name/prefix splitting plus PAX for paths or numeric fields that do not fit. Prevalidate Unicode, sizes, unsupported names, and duplicate output paths before showing a transfer code. Calculate advertised archive size from the same serialization rules as the emitted headers, extensions, padding, and trailer; no silent truncation.
- [x] **F11 — Finish the picker lifecycle.** Retain the user-selected handle across negotiation, open the writable only when ready, and route all failure paths to abort. Separate unsupported API, permission failure, user cancellation, and an explicitly chosen memory fallback. Display the actual chosen output name/path where the platform permits it.

Exit gate: an existing output remains unchanged on every pre-commit failure; failed close/rename/extraction never produces a success acknowledgement; no partial multi-root archive publication; successful publication is retained if only the final network acknowledgement is lost.

## Phase 4 — Add bounded streaming, control handling, and liveness

Depends on Phase 2 ordering and Phase 3 sink contracts. This is the principal protocol coordination change.

- [x] **F05/F14 — Give each direction one read owner and each encrypted stream one write-order owner.** Continuously process inbound control traffic even while sending file data. Serialize sequence reservation and physical writes for data, heartbeat, credit, cancellation, and completion; reserve bounded control capacity without allowing a later nonce to overtake an already reserved frame.
- [x] **F05/F09 — Add explicit receiver credits.** Negotiate a bounded byte window for peers that need application flow control, particularly DataChannels. Replenish credits after consumption, not after enqueueing. Bound both wire buffering and decoded payload work; compression must not turn a wire-byte allowance into unbounded output. Validate grants, overflows, over-credit data, and zero/tiny-frame floods. Do not require data credit for bounded liveness/terminal controls.
- [x] **F14 — Distinguish idle input from a dead peer.** Send real heartbeats through the serialized writer; refresh peer liveness on validated inbound protocol activity, not local send progress. Waiting for input, output I/O, or finalization is an explicit state with bounded resource ownership. A blocked network write still needs its own deadline; queued heartbeats cannot bypass a stuck socket.
- [x] **F14 — Cancel the complete pipeline.** One transfer-scoped context propagates read/write failure, heartbeat expiry, and user cancellation to producers, consumers, queues, sockets, and owned pipes/files. Explicitly support interruptible CLI stdin. Do not claim arbitrary caller-provided `io.Reader` implementations are cancellable; require a cancellation/close contract where needed and do not close caller-owned resources without that contract.
- [x] **F10 — Stream browser single-file sends.** Read bounded slices and use the existing incremental SHA-256 path while transmitting. Eliminate whole-file `arrayBuffer()` and the pre-send full-file digest. Preserve the final digest and byte-count checks, and keep large-file memory proportional to configured windows rather than file size.
- [x] **Compatibility — Introduce the next protocol version where needed.** Candidate proof/selection and credits use transfer v3; signaling remains v2. Automatically negotiate v3 between updated peers and v2 with an old peer using transcript-bound public-key capability markers. Authenticate before accepting the result; test stripping either/both markers. No manual version flag or browser checkbox is needed. Never retry a failed connection at a lower version. Legacy compatibility disables parallel TCP and warns without prompting. Retain updated peers' local decode/queue/quota/output protections and release cross-version regressions against old clients and servers; do not claim old peers are repaired.

Exit gate: a live stdin stream may pause beyond the old 15-second timeout; a dead peer still terminates promptly; a slow disk throttles a cooperative sender without growing queues; reverse-direction traffic stays bounded during long sends.

## Phase 5 — Close server abuse and distribution hardening gaps

Can follow the containment release without waiting for throughput optimization. Deployed policy changes require operator approval; this plan authorizes no production changes.

- [x] **F08 — Restrict forwarding trust.** Validate immediate proxy identity against configured addresses/CIDRs and resolve a multi-hop chain from the trusted side. Ignore spoofable values on direct connections. Reuse this identity for all rate/session/socket limits. Include migration instructions for common reverse-proxy arrangements.
- [x] **F13 — Bound TURN issuance.** Cache one bounded issuance outcome in the session so repeated requests from either participant return the same credentials or a defined denial, not renewed lifetimes. Include an opaque session identity in the expiry-based username, bound TTL, and rate-limit issuance globally/per client identity. Do not rely on the five-second wait or official-client consent as authentication.
- [ ] **F13 — Define actual relay policy.** Provide a reviewed coturn deployment example with allocation, bandwidth, total-capacity, and destination-address restrictions, including private/link-local/loopback targets. Document residual abuse: anonymous clients can create new sessions and use legitimately issued credentials elsewhere. Renewal, if needed for reconnects, needs a bounded explicit policy; existing allocation lifetime must be verified against the chosen TURN configuration.
- [x] **O09 — Harden runtime and CI.** Run both Docker variants as a dedicated non-root identity; provide writable persistent config/ACME storage and an explicit low-port strategy. Pin privileged actions, builder images, and downloaded release tools to reviewed immutable identities or verified hashes. Minimize job permissions and maintain an intentional update process. Preserve `CGO_ENABLED=0` for release binaries.
- [ ] **O10 — Verify distributed artifacts with an independent trust anchor.** Extend the existing macOS/Windows/package signing workflow rather than replace it. Publish attestations covering final artifacts after platform signing/notarization and document optional manual verification with a pinned signer identity and approved tag. Test tampering, wrong signer/platform, absent verification support, and stale releases against a documented rollback policy. User-directed adjustment on 8 September 2026: bootstrap must not require `gh`; shell/PowerShell normally check the same fixed release's SHA-256 manifest with standard tools. The subsequently requested explicit first-argument `--insecure-skip-checksum` bypass skips manifest/hash checks with a stderr warning, while preserving release/platform URL validation. The default trusts GitHub HTTPS and is not independent signer verification; the stronger automatic-bootstrap requirement is no longer claimed as implemented.
- [x] **O10 — Correct the endpoint trust model.** Update README, SECURITY, and the served agent guide: signaling compromise does not reveal CLI keys, but a compromised web/bootstrap host can deliver hostile code. Verification code downloaded from that same compromised host cannot remove this trust. Offer independently verified installed CLI/package workflows; do not claim a self-hosted web app can protect itself from its own code-distribution host.

Exit gate: forwarded-IP spoofing and credential renewal are bounded under documented deployment assumptions; non-root images retain TLS/config functionality; supported verified-download paths reject modified artifacts before execution. Provisioning signing trust and production relay quotas is an explicit release prerequisite, not something to assume completed locally.

## Phase 6 — Remove measured throughput and allocation bottlenecks

Depends on bounded pipeline ownership from Phases 2–4. F10's whole-file browser buffering is a correctness fix and does not wait for this phase.

- [x] **O01 — Avoid one socket blocking all parallel writers.** Introduce bounded per-stream write queues if the baseline confirms head-of-line blocking. Maintain nonce order within each stream, global data sequence mapping, a shared byte budget, and a completion barrier. Bound queued work so a stalled early sequence cannot cause unlimited useful-looking work on other streams. Fail/cancel a dead stream explicitly unless a separately designed safe retry protocol exists.
- [x] **O02 — Parallelize compression only where useful.** Profile compression separately from encryption. If compression dominates, use a bounded worker stage with stable global chunk assignment and ordered per-stream writes. Cap worker count and compressor memory; compare compressible and already-compressed input. Do not silently mix raw/zstd chunks without an explicit supported encoding contract.
- [x] **O03 — Coalesce archive reads.** Fill normal archive chunks across short `io.Pipe` reads. Preserve empty/final-chunk semantics and hashing. For interactive stdin, use a bounded latency-aware flush policy rather than waiting indefinitely for a full chunk.
- [x] **O04 — Reduce avoidable copies and allocation.** Profile Go frame/plaintext buffers and browser concatenation/slicing. Introduce explicit buffer ownership before pooling or reusing storage; do not mutate bytes still referenced by Web Crypto, DataChannel sends, writers, or queued frames. Avoid retaining unusually large allocations in pools.
- [ ] **Measurement gate.** Record throughput, time to first byte, CPU, allocations, peak RSS/browser memory, queue high-water marks, and cancellation latency. Compare the original revision, the secure baseline, and each optimization separately. Retain a complexity-increasing optimization only for a repeatable improvement; if an observation is not a material bottleneck, close it with measurements and rationale rather than unnecessary code.

Exit gate: streaming memory remains flat as file sizes grow, every queue is bounded under stalls, and accepted optimizations show a repeatable benefit without new correctness or compatibility regressions.

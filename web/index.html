Security

What sp2p protects, and what you still trust.

The threat model in plain language. The full details live in the security model.

Encrypted end to end, every time

Each transfer starts with fresh X25519 keys. HKDF-SHA256 derives a separate AES-256-GCM key for each direction, and both sides confirm the keys before any data moves, so a wrong code or a meddling middleman aborts the transfer.

The link is the key

A share link looks like /r#SESSION-SEED. Browsers never send the part after # to a server, and the receive page clears it from the address bar once read. The server learns the session ID; the 128-bit seed that keys the encryption never reaches it. Anyone holding the whole link can receive, so share it like a password. Both screens show a verification code you can compare for extra assurance.

The server introduces, it doesn't carry

The signaling server passes public keys and connection candidates between the two peers, plus an encrypted name-and-size preview it can't read. When a direct connection works, file data never touches it. Like any server you connect to, it does see IP addresses and timing.

Relays need consent from both sides

If no direct path exists, a TURN relay can carry the stream as a last resort. It sees only ciphertext and connection metadata, and it's never used unless both the sender and the receiver agree, through a browser or CLI prompt, an agent's explicit allow, or -allow-relay (flag or config).

You trust the code you run

This page's JavaScript and the curl | sh and PowerShell one-liners come from this host. The one-liners check a pinned CLI release against its checksums.txt before running it, then delete it. That trusts this host and GitHub's HTTPS; it isn't independent signature verification, and encryption can't help if the host itself serves altered code. For a stronger boundary, install a release you verify or self-host the server.

Agents follow a guide you can read

Agent prompts point your AI agent at /llm, a plain Markdown guide. The agent then runs the sp2p CLI on your machine with your permissions, so review its commands as you would your own. A relay still needs an explicit allow.
